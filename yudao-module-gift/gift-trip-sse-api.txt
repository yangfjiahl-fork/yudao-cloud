Gift 旅行规划 C 端接口
=====================

更新日期：2026-09-01

一、通用约定
------------

- API 前缀：`/app-api`。
- 全部接口需要会员登录态：`Authorization: Bearer <accessToken>`；多租户请求同时传 `tenant-id`。
- 所有编号字段（如 `conversationId`、`messageId`、`slotId`）按字符串处理，不要转成 JavaScript `number`。
- 普通接口统一返回：`{"code":0,"msg":"","data":...}`。
- 流式接口使用 `POST + text/event-stream`。建议使用 `fetch + ReadableStream`；每帧格式为 `data:{...}\n\n`，业务内容位于 `data`。

二、会话接口
------------

### 1. 创建会话

`POST /app-api/ai/chat/conversation/create`

请求体可为空；已知所在地时可传：

    {
      "provinceId":"330000",
      "cityId":"330100",
      "districtId":"330106"
    }

响应为单帧 SSE：

    data:{"code":0,"msg":"","data":{
      "event":"created",
      "conversationId":"1781604279872581776",
      "messageId":"1781604279872581777",
      "content":"请告诉我出发地、目的地、出发日期、旅行天数、同行人数和预算，我来帮你规划旅程。"
    }}

保存 `conversationId`；`content` 可作为首条助手消息展示。

### 2. 会话列表

`GET /app-api/ai/chat/conversation/list`

`data` 为数组，单项字段：

    {
      "id":"1781604279872581776",
      "title":"2026-10-01 杭州",
      "pinned":false,
      "provinceId":"330000",
      "cityId":"330100",
      "districtId":"330106",
      "createTime":"2026-09-01 21:30:00"
    }

### 3. 更新会话

`PUT /app-api/ai/chat/conversation/update`

    {
      "id":"1781604279872581776",
      "title":"国庆杭州亲子游",
      "pinned":true
    }

`title`、`pinned` 均为可选字段。成功时 `data=true`。

### 4. 删除会话

`DELETE /app-api/ai/chat/conversation/delete?id=1781604279872581776`

成功时 `data=true`。

三、消息与 SSE
---------------

### 1. 查询消息历史

`GET /app-api/ai/chat/message/list-by-conversation-id?conversationId=1781604279872581776`

`data` 为消息数组：

    {
      "id":"1781604279872581780",
      "replyId":"0",
      "type":"assistant",
      "content":"已为你生成杭州三日行程。",
      "itinerary": { },
      "createTime":"2026-09-01 21:31:00"
    }

- `itinerary` 仅行程消息存在；前端用它直接恢复行程卡片。
- 普通文本消息的 `itinerary` 为 `null` 或不存在。

### 2. 发送消息

`POST /app-api/ai/chat/message/send-stream`

请求头增加：

    Accept: text/event-stream

请求体：

    {
      "conversationId":"1781604279872581776",
      "content":"我计划10月1日从上海去杭州，玩3天，2人，人均预算2000元"
    }

前端可先乐观展示用户 `content`；助手侧内容以 SSE 事件为准。

### 3. SSE 事件

| 事件 | 前端需要处理的字段 | 处理方式 |
| --- | --- | --- |
| `accepted` | `conversationId`、`content` | 开始本轮 loading。 |
| `stage` | `stage`、`content` | 更新 loading 文案，不写入聊天记录。`stage` 可能为 `INTAKE`、`FOLLOW_UP`、`ASSEMBLE`。 |
| `intake_completed` | `content`、`missingRequired`、`suggestions` | 可展示本轮摘要；不创建正式聊天消息。 |
| `question` | `messageId`、`content`、`missingRequired`、`suggestions` | 创建一条助手文本消息并展示胶囊。 |
| `itinerary_skeleton` | `messageId`、`content`、`itinerary`、`suggestions` | 创建一条助手行程消息，用 `itinerary` 渲染或替换行程卡。 |
| `done` | `conversationId` | 结束 loading。 |
| `error` | `conversationId`、`content` | 展示错误并结束 loading。 |

常见事件顺序：

- 信息尚未收集完整，或必填信息已完成但仍在补充可选项时：`accepted → stage(INTAKE) → stage(FOLLOW_UP) → intake_completed → question → done`。
- 用户点击“立即生成行程”后：`accepted → stage(INTAKE) → stage(ASSEMBLE) → itinerary_skeleton → done`。
- `intake_completed`、`question` 的 `missingRequired` 为空，不代表本轮一定生成行程；前端仍需展示 `question` 及其中的“立即生成行程”胶囊。

事件字段示例：

    {
      "event":"question",
      "stage":"INTAKE",
      "conversationId":"1781604279872581776",
      "messageId":"1781604279872581780",
      "content":"你还想补充旅行偏好或同行人情况吗？",
      "missingRequired":[],
      "suggestions":[
        {"label":"亲子友好","content":"希望行程亲子友好"},
        {"label":"美食与人文","content":"偏好美食和人文"},
        {"label":"立即生成行程","content":"请立即生成行程"}
      ]
    }

### 4. 胶囊交互

- `suggestions` 最多 5 项；每项都有 `label`（展示文案）和 `content`（发送内容）。
- 点击胶囊后，将其 `content` 原样作为下一次 `/send-stream` 的 `content` 提交。
- 当 `missingRequired` 为空时，前端仍应展示 `question` 及胶囊；其中会包含“立即生成行程”，用户也可以继续自由输入补充信息。
- 用户选择“立即生成行程”后，等待本轮的 `itinerary_skeleton`；不要自行拼装行程。

四、行程骨架
------------

`itinerary_skeleton.itinerary` 和消息历史中的 `itinerary` 使用同一结构：

    {
      "version":1,
      "overview":{
        "slot":"TRIP_OVERVIEW",
        "label":"行程总览",
        "status":"PENDING",
        "city":"杭州",
        "skeleton":"行程总览待生成"
      },
      "daily_itinerary":[
        {
          "day":1,
          "date":"2026-10-01",
          "overview":{
            "slot":"DAY_OVERVIEW",
            "label":"每日总览",
            "status":"PENDING",
            "city":"杭州",
            "skeleton":"每日总览待生成"
          },
          "slots":[
            {
              "slot":"MORNING",
              "label":"上午",
              "status":"PENDING",
              "city":"杭州",
              "poiId":"B0...",
              "poiName":"西湖",
              "area":"杭州",
              "longitude":"120.15",
              "latitude":"30.25",
              "suggestedStayMinutes":150,
              "skeleton":"游览西湖"
            }
          ]
        }
      ],
      "transport":{
        "arrival":{"status":"PENDING","city":"杭州","skeleton":"抵达杭州的交通待确认"},
        "departure":{"status":"PENDING","city":"杭州","skeleton":"从杭州返程的交通待确认"}
      },
      "citation_ids":[]
    }

- `overview` 是行程总览节点；前端以 `day=0`、`slot=TRIP_OVERVIEW` 调用节点补全接口获得模型生成的总览文案。
- 每个 `daily_itinerary` 的 `overview` 是每日总览节点；前端以该日 `day`、`slot=DAY_OVERVIEW` 调用节点补全接口获得模型生成的每日总览文案。
- `daily_itinerary` 按 `day` 展示；`date` 可能不存在。
- 每日 `slots` 的类型为 `MORNING`、`LUNCH`、`AFTERNOON`、`DINNER`、`ACCOMMODATION`。
- 每日可选 `planning` 字段由后端确定性排程写入，包含 `solver`、`status`、`routeDataStatus`、`budgetStatus`、`droppedNodeIds` 及日间起止时间；前端可用于展示“已校验”或“已降级”，缺失时按旧骨架处理。
- 当每日候选不足或完整排程不可行时，后端会在不跳过必去景点、午晚餐和住宿约束的前提下减少当日景点数量；`status` 仍为 `FEASIBLE`，并通过可选 `selectionStatus=DEGRADED`、`requestedScenicCount`、`selectedScenicCount` 标识降级结果。
- 节点可选 `plannedStartTime`、`plannedEndTime`、`travelMinutesFromPrevious`、`routeStatus`、`planningStatus`；它们表示当前行程版本的排程结果，前端不应自行重排。
- 节点字段可能因暂无候选而缺失 `poiId`、`poiName`、经纬度或停留时长；前端应使用 `skeleton` 兜底展示。
- `status` 初始为 `PENDING`；补全成功后以节点补全接口响应为准。

五、节点补全
------------

用户展开行程节点时调用：

`POST /app-api/ai/chat/message/itinerary/slot/resolve`

    {
      "conversationId":"1781604279872581776",
      "messageId":"1781604279872581790",
      "day":1,
      "slot":"MORNING"
    }

- `day`：日程从 `1` 开始；交通节点使用 `0`。
- `slot`：行程总览使用 `TRIP_OVERVIEW`（`day=0`）；每日总览使用 `DAY_OVERVIEW`（`day>=1`）；日程节点使用 `MORNING`、`LUNCH`、`AFTERNOON`、`DINNER`、`ACCOMMODATION`；交通节点使用 `ARRIVAL`、`DEPARTURE`。

响应：

    {
      "code":0,
      "msg":"",
      "data":{
        "messageId":"1781604279872581790",
        "slotId":"1781604279872581791",
        "day":1,
        "slot":"MORNING",
        "status":"RESOLVED",
        "detail":"西湖游览建议",
        "candidates":[{}],
        "citationIds":[],
        "transportSegments":[
          {
            "fromPoiId":"hotel-1",
            "fromPoiName":"西湖舒适酒店",
            "toPoiId":"poi-1",
            "toPoiName":"西湖",
            "distanceMeters":840,
            "durationMinutes":12,
            "mode":"WALKING",
            "provider":"gaode",
            "status":"VERIFIED"
          }
        ],
        "weather":{
          "city":"杭州",
          "temperature":"24",
          "condition":"晴",
          "humidity":"55",
          "windDirection":"东风",
          "windPower":"3级",
          "queryTime":"2026-09-01 21:31:00"
        }
      }
    }

- 总览节点的模型生成文本在 `detail` 返回，`candidates`、`citationIds`、`weather` 可为空或不存在，前端需兼容。
- `status` 可能为 `PENDING`、`RESOLVED` 或 `FAILED`；失败时保留骨架展示并允许重试。
- `transportSegments` 为当前 `day` 全部相邻 POI（含住宿点）的批量测距结果；`day=0` 时为空数组。每段含距离、耗时、出行方式和状态；`status=VERIFIED` 表示高德路径规划结果，`ESTIMATED` 表示高德不可用时的本地估算。`ESTIMATED` 段的 `provider` 可为空。前端可直接用于当天各 POI 间的距离展示。

六、按天获取交通路线
--------------------

用户打开某一天的地图时调用：

`POST /app-api/ai/chat/message/itinerary/route/resolve`

    {
      "conversationId":"1781604279872581776",
      "messageId":"1781604279872581790",
      "day":1
    }

响应：

    {
      "code":0,
      "msg":"",
      "data":{
        "messageId":"1781604279872581790",
        "day":1,
        "status":"VERIFIED",
        "transportSegments":[
          {
            "fromPoiId":"B0...",
            "fromPoiName":"西湖国宾馆",
            "fromLongitude":"120.0900",
            "fromLatitude":"30.1950",
            "toPoiId":"B0...",
            "toPoiName":"断桥残雪",
            "toLongitude":"120.1000",
            "toLatitude":"30.2000",
            "mode":"WALKING",
            "distanceMeters":840,
            "durationMinutes":12,
            "provider":"gaode",
            "status":"VERIFIED",
            "routePoints":[
              {"longitude":120.0900,"latitude":30.1950},
              {"longitude":120.1000,"latitude":30.2000}
            ]
          }
        ]
      }
    }

- 坐标均为高德 GCJ-02；`routePoints` 可直接绘制地图折线。
- 顶层和单段 `status` 为 `VERIFIED`、`ESTIMATED` 或 `PENDING`。`ESTIMATED` 时可使用虚线或“预估路线”样式；`PENDING` 时显示无路线提示。
- `transportSegments` 可能为空，前端须兼容。

七、前端调用顺序
----------------

1. 创建或选择会话。
2. 使用 `/send-stream` 发送用户消息，按 SSE 渲染 `question` 或 `itinerary_skeleton`。
3. 收到 `question` 时展示 `suggestions`；点击后继续调用 `/send-stream`。
4. 收到 `itinerary_skeleton` 后保存 `messageId`，按可见卡片调用 `/itinerary/slot/resolve`；该响应已包含当前天的 `transportSegments`，可直接用于距离和路线展示。
5. 需要重新获取整天路线、或尚未解析任一日程节点时，再调用 `/itinerary/route/resolve`。
6. 冷启动或返回页面时，使用消息历史接口恢复聊天和行程卡。
