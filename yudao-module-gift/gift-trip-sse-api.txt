Gift 旅行规划 C 端接口
=====================

更新日期：2026-09-19

一、通用约定
------------

- API 前缀：`/app-api`。
- 全部接口需要会员登录态：`Authorization: Bearer <accessToken>`；多租户请求同时传 `tenant-id`。
- 所有编号字段（如 `conversationId`、`messageId`、`slotId`）按字符串处理，不要转成 JavaScript `number`。
- 普通接口统一返回：`{"code":0,"msg":"","data":...}`。
- 流式接口使用 `POST + text/event-stream`，每帧格式为 `data:{...}\n\n`。所有帧统一使用 `CommonResult`：前端先读取外层 `code`、`msg`、`data`，AG-UI 事件对象位于 `data`。
- 旅行 Agent 的执行方式由服务端决定；前端不传 Agent 标识、模型参数、工作空间或 API Key，也不应依据后端实现入口分支协议。

二、会话接口
------------

### 1. 创建会话

`POST /app-api/ai/chat/conversation/create`

请求体可为空；已知所在地时可传：

    {
      "provinceId":"330000",
      "cityId":"330100",
      "districtId":"330106"
    }

响应为单帧 SSE：

    data:{"code":0,"msg":"","data":{
      "event":"created",
      "conversationId":"1781604279872581776",
      "messageId":"1781604279872581777",
      "content":"请告诉我出发地、目的地、同行人数，以及开始和结束日期或旅行天数，我来帮你规划旅程。预算可以稍后补充。"
    }}

保存 `conversationId`；响应中的 `content` 为助手首条消息内容。

### 2. 会话列表

`GET /app-api/ai/chat/conversation/list`

`data` 为数组，单项字段：

    {
      "id":"1781604279872581776",
      "title":"2026-10-01 杭州",
      "pinned":false,
      "provinceId":"330000",
      "cityId":"330100",
      "districtId":"330106",
      "createTime":"2026-09-01 21:30:00"
    }

### 3. 更新会话

`PUT /app-api/ai/chat/conversation/update`

    {
      "id":"1781604279872581776",
      "title":"国庆杭州亲子游",
      "pinned":true
    }

`title`、`pinned` 均为可选字段。成功时 `data=true`。

### 4. 删除会话

`DELETE /app-api/ai/chat/conversation/delete?id=1781604279872581776`

成功时 `data=true`。

三、消息与 SSE
---------------

### 1. 查询消息历史

`GET /app-api/ai/chat/message/list-by-conversation-id?conversationId=1781604279872581776`

`data` 为消息数组：

    {
      "id":"1781604279872581780",
      "replyId":"0",
      "type":"assistant",
      "content":"已为你生成杭州三日行程。",
      "itinerary": { },
      "createTime":"2026-09-01 21:31:00"
    }

- `itinerary` 仅行程消息存在。
- 普通文本消息的 `itinerary` 为 `null` 或不存在。

### 2. 运行旅行 Agent（AG-UI）

`POST /app-api/ai/chat/message/managed/run`

请求头：

    Content-Type: application/json
    Accept: text/event-stream

请求体遵循 AG-UI `RunAgentInput` 的核心字段：

    {
      "threadId":"1781604279872581776",
      "runId":"7b26e4e6-5bdf-4488-8c7b-3f16dd090d2b",
      "messages":[
        {
          "id":"e0aa3e40-8f19-4ed0-b9b3-7ae6caea1234",
          "role":"user",
          "content":"我计划10月1日从上海去杭州，玩3天，2人，人均预算2000元"
        }
      ]
    }

- `threadId` 是已创建的旅行 `conversationId` 的字符串形式；服务端按当前登录会员校验其归属。
- `runId` 由客户端为本轮运行生成并保持唯一；它不等于 `messageId`。
- 当前旅行入口只接受一条 `role=user` 的纯文本消息。会话历史由服务端保存，不能通过 `messages` 覆盖；`state`、`tools`、`context`、`forwardedProps` 不是本期输入能力。
- 本接口同时覆盖信息收集、可选信息补充和行程生成；通过阶段事件及后续卡片区分当前流程，不能为信息收集改用其他接口。
- 本接口每帧均返回 `{"code":0,"msg":"","data":{...AG-UI event...}}`；前端统一解出 `data` 后再按 AG-UI 的 `type` 分发。这是唯一受支持的旅行规划 SSE 入口；`/run` 与已移除的 `/send-stream` 都不是前端联调入口。
- 鉴权、请求校验或会话归属校验在 SSE 建立前失败时，服务端返回普通 `CommonResult` 错误响应，而不是 `RUN_ERROR` 事件。

### 3. AG-UI SSE 事件

所有帧均只使用 `data:`；事件类型由 `CommonResult.data.type` 判定。客户端必须先按 SSE 规范重组完整帧，再反序列化 JSON、校验外层 `code`、提取 `data`；不能按网络分块解析。

| AG-UI `type` | 字段 | 旅行规划语义 |
| --- | --- | --- |
| `RUN_STARTED` | `threadId`、`runId` | 本轮运行已开始；首帧。 |
| `ACTIVITY_SNAPSHOT` | `messageId`、`activityType=TRIP_PROGRESS`、`content` | 当前阶段快照。`content.stage` 为 `INTAKE`、`FOLLOW_UP` 或 `ASSEMBLE`，`content.content` 是可展示进度文字；同一 `messageId` 的后续快照应替换旧进度。 |
| `CUSTOM`，`name=trip_progress_card` | `value.cardId`、`value.messageId`、`value.stage`、`value.content`、`value.state` | 稳定的进度卡片。`cardId`、`messageId` 均为 `trip-progress-{runId}`；同 id 的快照直接替换。`state=active` 表示仍在处理，`completed` 表示本轮已输出追问或行程结果。 |
| `CUSTOM`，`name=trip_intake_completed` | `value.content`、`value.missingRequired`、`value.inputCards` | 后端已校验的信息收集结果。 |
| `TEXT_MESSAGE_START` / `TEXT_MESSAGE_CONTENT` / `TEXT_MESSAGE_END` | `messageId`、`role=assistant`、`delta` | 已持久化的助手追问或行程摘要。一个消息会有多个 `TEXT_MESSAGE_CONTENT`，客户端必须按到达顺序追加同一 `messageId` 的 `delta`，直至 `TEXT_MESSAGE_END`。 |
| `CUSTOM`，`name=trip_question_card` | `value.cardId`、`value.messageId`、`value.missingRequired`、`value.inputCards` | 追问卡片，位于对应文本结束后。`cardId=trip-question-{messageId}`；所有胶囊和表单控件统一渲染 `inputCards`。 |
| `CUSTOM`，`name=trip_itinerary_card` | `value.cardId`、`value.messageId`、`value.itinerary` | 行程卡片，位于对应文本结束后。`cardId=trip-itinerary-{messageId}`。只使用这里或兼容事件中服务端已保存的 `itinerary` 渲染真实行程。 |
| `CUSTOM`，`name=trip_question` | `value.messageId`、`value.missingRequired`、`value.inputCards` | 兼容事件名，语义与 `trip_question_card` 相同。 |
| `CUSTOM`，`name=trip_itinerary_skeleton` | `value.messageId`、`value.itinerary` | 兼容事件名，语义与 `trip_itinerary_card` 相同。 |
| `RUN_FINISHED` | `threadId`、`runId`、`outcome`、`result.conversationId` | 正常终态。`outcome.type=success`。 |
| `RUN_ERROR` | `threadId`、`runId`、`code`、`message` | 已建立 SSE 后发生的失败终态；收到后不得再等待 `RUN_FINISHED`。 |

常见事件顺序：

- 每个阶段：`ACTIVITY_SNAPSHOT → CUSTOM(trip_progress_card, state=active)`；两者均保留，旧客户端继续使用 `ACTIVITY_SNAPSHOT`。
- 信息尚未收集完整，或必填信息已完成但仍在补充可选项时：`RUN_STARTED → 阶段事件* → CUSTOM(trip_intake_completed) → TEXT_MESSAGE_START → TEXT_MESSAGE_CONTENT+ → TEXT_MESSAGE_END → CUSTOM(trip_question_card) → CUSTOM(trip_question) → CUSTOM(trip_progress_card, state=completed) → RUN_FINISHED`。
- 触发行程生成时：`RUN_STARTED → 阶段事件* → CUSTOM(trip_intake_completed) → TEXT_MESSAGE_START → TEXT_MESSAGE_CONTENT+ → TEXT_MESSAGE_END → CUSTOM(trip_itinerary_card) → CUSTOM(trip_itinerary_skeleton) → CUSTOM(trip_progress_card, state=completed) → RUN_FINISHED`。
- `missingRequired=[]` 仅表示出发地、目的地、出行人数已完整，并且“完整的开始/结束日期”或“旅行天数”至少提供了一项；仅提供日期区间时，后端按首尾日期都计入自动换算天数。仍可能存在预算等可选信息追问和“立即生成行程”建议。未提供预算时按每人每天 500 元且不含往返交通处理。
- 服务端不会向本接口发送 `trip_model_delta`。模型原始 JSON、系统提示词和推理过程均不是客户端协议内容；不得将它们作为文本或卡片展示。
- `RUN_STARTED`、`RUN_FINISHED`、`RUN_ERROR` 是单轮边界事件；其余事件均应按 `runId` 和关联的 `messageId` 归并，避免并发运行时互相覆盖。

追问的事件片段示例：

    data:{"code":0,"msg":"","data":{"type":"TEXT_MESSAGE_START","messageId":"1781604279872581780","role":"assistant"}}

    data:{"code":0,"msg":"","data":{"type":"TEXT_MESSAGE_CONTENT","messageId":"1781604279872581780","delta":"你还想补充旅行"}}

    data:{"code":0,"msg":"","data":{"type":"TEXT_MESSAGE_CONTENT","messageId":"1781604279872581780","delta":"偏好或同行人情况吗？"}}

    data:{"code":0,"msg":"","data":{"type":"TEXT_MESSAGE_END","messageId":"1781604279872581780"}}

    data:{"code":0,"msg":"","data":{"type":"CUSTOM","name":"trip_question_card","value":{"cardId":"trip-question-1781604279872581780","stage":"INTAKE","messageId":"1781604279872581780","missingRequired":[],"inputCards":[{"id":"trip-quick-options","type":"SINGLE_SELECT","schemaVersion":1,"field":"userMessage","title":"快捷选择","props":{"selectionMode":"SINGLE","options":[{"label":"亲子友好","value":"希望行程亲子友好","content":"希望行程亲子友好"},{"label":"立即生成行程","value":"请立即生成行程","content":"请立即生成行程"}]},"submit":{"mode":"OPTION_CONTENT"}}]}}}

    data:{"code":0,"msg":"","data":{"type":"CUSTOM","name":"trip_question","value":{"stage":"INTAKE","messageId":"1781604279872581780","missingRequired":[],"inputCards":[{"id":"trip-quick-options","type":"SINGLE_SELECT","schemaVersion":1,"field":"userMessage","title":"下一步","props":{"selectionMode":"SINGLE","options":[{"label":"立即生成行程","value":"请立即生成行程","content":"请立即生成行程"}]},"submit":{"mode":"OPTION_CONTENT"}}]}}}

### 4. `inputCards` 字段

`inputCards` 是结构化追问控件数组，也是所有胶囊和表单输入的唯一协议字段，不再输出 `suggestions`。每张卡片都使用稳定信封：

- 公共字段：`id`、`type`、`schemaVersion`、`field`、`title`；二选一的卡片还带 `requiredGroup`。
- `props`：当前 `type` 的展示和校验参数。新增卡片类型只扩展自己的 `props`，不改变事件结构。
- `submit`：把交互值转换成用户消息的规则。`mode=OPTION_CONTENT` 表示直接提交选项 `content`；`mode=TEMPLATE` 表示将选择值替换到 `contentTemplate`。

当前 `schemaVersion=1`，表示稳定信封的版本，而不是某个卡片组件的版本。前端建议使用 `type -> renderer` 注册表接入；遇到未注册的 `type` 或更高的 `schemaVersion` 时忽略该卡片并保留助手文本，不能导致整条消息渲染失败。

当前支持以下类型：

- `SINGLE_SELECT`：单选胶囊。缺少行程长度时返回天数选择，默认包含 2～7 天并允许自定义。
- `DATE_RANGE`：日期范围选择。与天数选择共享 `requiredGroup=trip-duration`，两张卡完成任意一张即可。`endDate` 不是全局必填字段；但选择日期范围卡提交时需同时给出开始、结束日期，服务端按首尾日期都计入换算天数。
- `MULTI_SELECT`：多选胶囊。询问用户想去哪些景点时使用，`field=mustVisit`；允许不选、选择一个或多个。

普通偏好、“立即生成行程”等原有胶囊统一输出为 `SINGLE_SELECT`，`field=userMessage`。

天数与日期范围示例：

    "inputCards":[
      {
        "id":"trip-duration-days",
        "type":"SINGLE_SELECT",
        "schemaVersion":1,
        "field":"days",
        "title":"选择出行天数",
        "requiredGroup":"trip-duration",
        "props":{
          "selectionMode":"SINGLE",
          "allowCustom":true,
          "options":[{"label":"3天","value":3,"content":"计划玩3天"}]
        },
        "submit":{"mode":"OPTION_CONTENT"}
      },
      {
        "id":"trip-duration-date-range",
        "type":"DATE_RANGE",
        "schemaVersion":1,
        "field":"dateRange",
        "title":"选择出行日期",
        "requiredGroup":"trip-duration",
        "props":{
          "fields":[
            {"name":"startDate","label":"开始日期"},
            {"name":"endDate","label":"结束日期","globallyRequired":false}
          ],
          "completeRangeRequired":true
        },
        "submit":{
          "mode":"TEMPLATE",
          "contentTemplate":"我计划{{startDate}}出发，{{endDate}}返程"
        }
      }
    ]

景点多选示例：

    {
      "id":"trip-must-visit",
      "type":"MULTI_SELECT",
      "schemaVersion":1,
      "field":"mustVisit",
      "title":"选择想去的景点",
      "props":{
        "selectionMode":"MULTIPLE",
        "minSelections":0,
        "maxSelections":2,
        "options":[
          {"label":"滇池","value":"我想去滇池","content":"我想去滇池"},
          {"label":"石林","value":"我想去石林","content":"我想去石林"}
        ]
      },
      "submit":{
        "mode":"TEMPLATE",
        "label":"确认选择",
        "contentTemplate":"我想去：{{contents}}",
        "emptyContent":"这些景点都不去"
      }
    }

前端提交仍复用普通用户消息：单选直接发送选项 `content`；日期范围按模板替换日期后发送；多选把所选项的 `content` 用中文逗号连接后替换 `{{contents}}`。不新增提交接口。

四、行程骨架
------------

`CUSTOM(name=trip_itinerary_skeleton).value.itinerary` 和消息历史中的 `itinerary` 使用同一结构：

    {
      "version":1,
      "overview":{
        "slot":"TRIP_OVERVIEW",
        "label":"行程总览",
        "status":"PENDING",
        "city":"杭州",
        "skeleton":"行程总览待生成"
      },
      "daily_itinerary":[
        {
          "day":1,
          "date":"2026-10-01",
          "overview":{
            "slot":"DAY_OVERVIEW",
            "label":"每日总览",
            "status":"PENDING",
            "city":"杭州",
            "skeleton":"每日总览待生成"
          },
          "slots":[
            {
              "slot":"MORNING",
              "label":"上午",
              "status":"PENDING",
              "city":"杭州",
              "poiId":"B0...",
              "poiName":"西湖",
              "area":"杭州",
              "longitude":"120.15",
              "latitude":"30.25",
              "suggestedStayMinutes":150,
              "skeleton":"游览西湖"
            }
          ]
        }
      ],
      "transport":{
        "arrival":{"status":"PENDING","city":"杭州","skeleton":"抵达杭州的交通待确认"},
        "departure":{"status":"PENDING","city":"杭州","skeleton":"从杭州返程的交通待确认"}
      },
      "citation_ids":[]
    }

- `overview` 是行程总览节点；使用 `day=0`、`slot=TRIP_OVERVIEW` 调用节点补全接口可获取模型生成的总览文案。
- 每个 `daily_itinerary` 的 `overview` 是每日总览节点；使用该日 `day`、`slot=DAY_OVERVIEW` 调用节点补全接口可获取模型生成的每日总览文案。
- `daily_itinerary` 按 `day` 排序；`date` 可能不存在。
- 每日 `slots` 的类型为 `MORNING`、`LUNCH`、`AFTERNOON`、`DINNER`、`ACCOMMODATION`。
- 每日可选 `planning` 字段由后端确定性排程写入，包含 `solver`、`status`、`routeDataStatus`、`budgetStatus`、`droppedNodeIds` 及日间起止时间。
- 当每日候选不足或完整排程不可行时，后端会在不跳过必去景点、午晚餐和住宿约束的前提下减少当日景点数量；`status` 仍为 `FEASIBLE`，并通过可选 `selectionStatus=DEGRADED`、`requestedScenicCount`、`selectedScenicCount` 标识降级结果。
- 节点可选 `plannedStartTime`、`plannedEndTime`、`travelMinutesFromPrevious`、`routeStatus`、`planningStatus`；它们表示当前行程版本的排程结果。
- 节点字段可能因暂无候选而缺失 `poiId`、`poiName`、经纬度或停留时长；此时 `skeleton` 仍会返回。
- `status` 初始为 `PENDING`；补全成功后以节点补全接口响应为准。

五、节点补全
------------

用户展开行程节点时调用：

`POST /app-api/ai/chat/message/itinerary/slot/resolve`

    {
      "conversationId":"1781604279872581776",
      "messageId":"1781604279872581790",
      "day":1,
      "slot":"MORNING"
    }

- `day`：日程从 `1` 开始；交通节点使用 `0`。
- `slot`：行程总览使用 `TRIP_OVERVIEW`（`day=0`）；每日总览使用 `DAY_OVERVIEW`（`day>=1`）；日程节点使用 `MORNING`、`LUNCH`、`AFTERNOON`、`DINNER`、`ACCOMMODATION`；交通节点使用 `ARRIVAL`、`DEPARTURE`。

响应：

    {
      "code":0,
      "msg":"",
      "data":{
        "messageId":"1781604279872581790",
        "slotId":"1781604279872581791",
        "day":1,
        "slot":"MORNING",
        "status":"RESOLVED",
        "detail":"西湖游览建议",
        "candidates":[{}],
        "citationIds":[],
        "transportSegments":[
          {
            "fromPoiId":"arrival-1",
            "fromPoiName":"杭州东站",
            "toPoiId":"poi-1",
            "toPoiName":"西湖",
            "distanceMeters":840,
            "durationMinutes":12,
            "mode":"WALKING",
            "provider":"gaode",
            "status":"VERIFIED"
          }
        ],
        "weather":{
          "city":"杭州",
          "temperature":"24",
          "condition":"晴",
          "humidity":"55",
          "windDirection":"东风",
          "windPower":"3级",
          "queryTime":"2026-09-01 21:31:00"
        }
      }
    }

- 总览节点的模型生成文本在 `detail` 返回，`candidates`、`citationIds`、`weather` 可为空或不存在。
- `status` 可能为 `PENDING`、`RESOLVED` 或 `FAILED`。
- `transportSegments` 为当前 `day` 的相邻节点批量测距结果；首日存在已确认 `transport.arrival` 经纬度时，以抵达机场/车站为首段起点，之后按 POI 相邻顺序计算，住宿仅为最后一段终点。到达点尚未确认坐标时，不会伪造“住宿 → 首个 POI”首段；`day=0` 时为空数组。市内交通默认 `mode=TAXI`，高德驾车路径作为出租车距离、耗时和轨迹依据。`status=VERIFIED` 表示高德路径规划结果，`ESTIMATED` 表示高德不可用时的本地估算。`ESTIMATED` 段的 `provider` 可为空。

六、按天获取交通路线
--------------------

用户打开某一天的地图时调用：

`POST /app-api/ai/chat/message/itinerary/route/resolve`

    {
      "conversationId":"1781604279872581776",
      "messageId":"1781604279872581790",
      "day":1
    }

响应：

    {
      "code":0,
      "msg":"",
      "data":{
        "messageId":"1781604279872581790",
        "day":1,
        "status":"VERIFIED",
        "transportSegments":[
          {
            "fromPoiId":"arrival-1",
            "fromPoiName":"杭州东站",
            "fromLongitude":"120.2200",
            "fromLatitude":"30.2900",
            "toPoiId":"B0...",
            "toPoiName":"断桥残雪",
            "toLongitude":"120.1000",
            "toLatitude":"30.2000",
            "mode":"WALKING",
            "distanceMeters":840,
            "durationMinutes":12,
            "provider":"gaode",
            "status":"VERIFIED",
            "routePoints":[
              {"longitude":120.2200,"latitude":30.2900},
              {"longitude":120.1000,"latitude":30.2000}
            ]
          }
        ]
      }
    }

- 坐标均为高德 GCJ-02。
- 顶层和单段 `status` 为 `VERIFIED`、`ESTIMATED` 或 `PENDING`。
- `transportSegments` 可能为空。
